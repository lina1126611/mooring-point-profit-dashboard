# Mooring Point — 경영지원 대시보드

프로젝트 수주형 엔지니어링 기업을 위한 2단 손익 대시보드.
**Python + Streamlit + SQLite**

> **학습·포트폴리오용 저장소입니다.** 특정 기업의 실제 회계 데이터는 포함하지
> 않습니다. 화면과 문서에 나오는 모든 금액·거래처·현장명은
> `scripts/generate_sample_data.py` 가 생성한 가상값이며, 실데이터 경로
> (`data/raw/`, `data/local/`, `data/pseudo/`, `db/*.db`)는 `.gitignore` 로
> 제외됩니다. → [실데이터 취급](#실데이터-취급)

---

## 무엇을 푸는가

수주형 엔지니어링 기업의 원가 회계에는 두 가지 공백이 반복해서 생긴다.

1. **일반적인 ERP는 고정비와 변동비를 구분해 주지 않는다.**
   그래서 *"현장에서 돈이 남았는데 최종적으로 왜 안 남았는지"* 를 설명할 수 없다.
2. **설계 인력의 맨데이(투입 인건비)가 원가에 안 잡히는 경우가 많다.**
   그 결과 프로젝트 이익률이 실제보다 과대표시된다.

현장 단위 이익은 보이는데 회사 전체 이익과의 간극이 설명되지 않는다.
이 간극 = **배부되지 않은 고정비 + 계상되지 않은 맨데이 인건비**.

## 핵심 설계 — 2단 손익 구조

```
[1단] 공헌이익 (현장이익)
      = 프로젝트 매출 − 변동비

[2단] 진짜 영업이익 (세전)
      = 공헌이익 − 배부된 고정비 − 맨데이 인건비
        ※ 배부된 고정비에는 차입금 이자가 포함된다
```

- **1단**은 현장이 벌어온 돈. 기존에 보고 있던 숫자.
- **2단**은 회사에 실제로 남는 돈. 안 보이던 숫자.

대시보드는 두 숫자를 **나란히** 놓고, 그 **차이를 항목별로 분해**해서
"왜 안 남았는지"에 답한다 (고정비 배부액 / 맨데이 인건비 / 이자비용).

### 2단은 '세전'이다 — 이름에 주의

회계 기준으로 **영업이익은 이자비용을 빼지 않는다**(이자는 영업외비용). 이
시스템은 이자를 고정비 풀에 넣어 함께 배부하므로, "진짜 영업이익"은 엄밀히는
영업이익이 아니라 **세전이익(경상이익)에 가깝다.** 이름은 현장에서 굳어진
용어라 유지하되, 화면·리포트에는 반드시 **(세전)** 을 병기한다.

**법인세는 이 구조에 넣지 않는다.** 이 프로젝트가 푸는 문제(고정비 미배부·맨데이
누락)와 무관하고, 전사 단위로만 산출되는 세금을 현장별로 배부하면 *자의적 배부를
하나 더 만드는 것*이기 때문이다. 또 법인세는 발생이 당기·납부가 이듬해라서
**2단 이익 ≠ 지금 쓸 수 있는 현금**이다. 자금 관점이 필요하면 손익을 3단으로
늘리지 말고 별도 화면으로 만든다.

## 화면

사이드바 메뉴를 **역할로** 나눈다. 대표가 실제로 쓰는 화면은 조회용 둘뿐이고,
엑셀 업로드·분류 수정·차입금 등록은 경리와 실무자의 일이다. 기능을 감추는 게
아니라 누구 화면인지를 메뉴에 드러낸다(관리용에는 ⚙ 표시).

| 그룹 | 페이지 | 내용 |
|---|---|---|
| **보기** | 아침 브리핑 | 오늘 상황 30초 요약 — 히어로 지표, 현장별 `공헌이익률 vs 진짜이익률(세전)`, 저수익·적자 경고 |
| **보기** | 리포트 | 경영 리포트 생성·내려받기 (템플릿 + 선택적 AI 코멘트) |
| 관리 ⚙ | 프로젝트 상세 | 손익 폭포차트, 거래 내역, 맨데이 입력 |
| 관리 ⚙ | 설정 | 차입금(등록 즉시 월이자 표시), 월 고정비, 고정비 배부기준, 표준일당 |
| 관리 ⚙ | 데이터 | 엑셀 업로드, 분류 수정(일괄 지정 포함), 재분류 |

폭포차트(매출→변동비→공헌이익→고정비→맨데이→진짜 영업이익)의 맨데이 구간은
색이 아니라 **빗금**으로 구분한다 — "ERP에 안 잡히던 원가가 여기 있다"가
이 차트의 요점이기 때문이다.

## 실행

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

python scripts/install_hooks.py          # ★ 실데이터 커밋 차단 (각자 한 번)
copy paths.local.example.json paths.local.json   # ★ 실데이터 위치 설정 후 경로 수정

python scripts/generate_sample_data.py   # 샘플 엑셀 생성 (data/sample/)
python scripts/load_sample_data.py       # db/mooring.db 적재 + 품질 점검
streamlit run app.py                     # http://localhost:8501
pytest                                   # 424 케이스
```

`install_hooks.py` 는 **클론한 사람이 각자 실행해야 한다.** `.git/hooks/` 는
커밋되지 않기 때문이다. 설치 확인은 `python scripts/install_hooks.py --check`.

## 설계 원칙

**모든 금액 계산은 pytest로 검증한다.** 이 프로젝트의 최우선 규칙이다.

- 손익 항등식을 회귀 테스트로 고정:
  `공헌이익 − 배부고정비 − 맨데이인건비 = 진짜 영업이익(세전)`
- 배부 로직은 **배부 총액이 원본 총액과 일치**하는지 검증 (반올림 잔차 포함)
- 통화는 원(KRW) 정수 저장. 부동소수점 누적 오차를 피한다.
- 손익 계산은 항상 **공급가액** 기준. 부가세는 매입세액공제로 환급되므로
  원가도 매출도 아니다. VAT 포함 총액은 자금흐름 확인용으로만 보관한다.

**모르면 모른다고 남긴다.** 규칙에 안 걸리는 거래는 `미분류` 로 두고
변동비·고정비 어느 쪽에도 넣지 않는다. 억지로 끼워 맞추면 손익이 조용히
틀어지기 때문이다. 대신 미분류 총액을 UI에 항상 노출한다.

같은 이유로 아래 두 가지도 별도 집계해 노출한다. 분류가 돼 있어서 미분류보다
발견이 늦은 누락들이다.

- **현장 미귀속 변동비** — 변동으로 분류됐지만 `project_id` 가 비어 어느 현장
  원가에도 안 잡히는 금액
- **원가행태 미등록 계정** — 매핑에 없어서 `해당없음` 이 되는데 `미분류` 도
  아니라서 미분류 집계에서까지 빠지는 계정. 금액이 어떤 화면에도 안 나타난다.

**사람이 판단할 것은 사람에게 남긴다.** 같은 (날짜+거래처+금액)이 반복되는 행은
`is_duplicate_suspect` 로 표시만 하고 자동 삭제하지 않는다 — 같은 날 같은 금액을
두 번 지급하는 정상 거래가 실제로 존재한다. 사람이 고친 분류는
`is_manual_override` 로 못 박아 재분류가 덮어쓰지 못하게 한다.

## 실데이터 취급

이 저장소는 공개다. 실제 회계 자료는 **저장소 폴더 밖**에 두고, 커밋 경로도
두 겹으로 막는다.

### 1) 위치 — 폴더 밖에 둔다

`.gitignore` 와 pre-commit 훅은 **커밋**을 막는다. **읽기는 막지 못한다.**
저장소 폴더를 AI 에이전트·코드 도구·백업 동기화에 물리면 그 안의 파일은 그냥
읽힌다. 그래서 경로 자체를 밖으로 옮긴다 — 관례가 아니라 위치로 막는 방식이다.

`paths.local.example.json` 을 `paths.local.json` 으로 복사하고 자기 PC 경로를 적는다.

```json
{
  "raw":    "C:/Users/이름/mooring-private/raw",
  "local":  "C:/Users/이름/mooring-private/local",
  "pseudo": "C:/Users/이름/mooring-private/pseudo"
}
```

환경변수 `MOORING_RAW_DIR` / `MOORING_LOCAL_DIR` / `MOORING_PSEUDO_DIR` 가 있으면
그쪽이 이긴다. 아무것도 없으면 저장소 내 `data/raw` 등으로 떨어지며 **스크립트가
경고를 찍는다** — 동작은 시키되 옮기게 만든다. 스크립트는 실행할 때마다 어느
경로를 읽었는지 출처와 함께 표시한다(`src/paths.py`).

| 성격 | 내용 | 공유 |
|---|---|---|
| `data/sample/` (저장소 안) | 생성된 가상 데이터 | 저장소에 포함 |
| `raw` | 원본 ERP export | **금지** |
| `local` | 가명 매핑표·검토표 (원본 그대로) | **금지** — 이게 새면 가명화가 무의미하다 |
| `pseudo` | 가명화 데이터 — 이름은 가려도 **금액은 실제값** | 사람이 직접 판단 |
| `db/*.db` | 적재된 SQLite | **금지** |

### 2) 커밋 차단 — 두 겹

1. **`.gitignore`** — 지정된 경로를 제외한다. 다만 *경로*만 보므로 다른 곳에
   두면 걸리지 않는다.
2. **pre-commit 훅** — 경로·파일명·매직바이트로 잡으므로 옮기거나 확장자를
   바꿔도 걸린다. `python scripts/install_hooks.py` 로 설치한다.

분류는 원본을 쥔 로컬에서 한다. 가명화 데이터로는 분류를 할 수 없다 —
사용처를 `가맹점_017` 로 바꾸면 "주유소니까 차량유지비"라는 판정 근거가
사라지기 때문이다(`src/local_llm.py`, `src/pseudonym.py`).

거래처명 기반 확정 판단은 `rules.py` 가 아니라 `data/local/거래처_계정.csv` 에
둔다(`src/local_overrides.py`). 규칙 파일에 적으면 실제 상호가 공개 저장소에
커밋되기 때문이다. **로직은 공개, 데이터는 로컬.**
