# PRD: 손익분석 — 2단 손익 구조 (P0-2)

> 이 문서는 `PRD_01_경영데이터통합.md` 가 예고한 후속 기능(P0-2)의 PRD이며,
> 동시에 현재 구현된 Python + Streamlit + SQLite 시스템의 요구사항 명세다.
> 기능 요구사항에 **구현 현황**을 함께 적었다 — 문서와 코드가 어긋나면 문서가
> 먼저 쓸모를 잃기 때문이다.
>
> 실제 회계 데이터는 이 문서에 포함하지 않는다. 예시 금액·거래처·현장명은
> 모두 가상값이다.

## 1. 개요

통합 원장(P0-1의 산출물)을 입력으로 받아, 프로젝트별·전사 손익을 **2단 구조**로
계산하는 기능. 1단은 현장이 벌어온 돈(공헌이익), 2단은 회사에 실제로 남는
돈(세전이익)이다. 두 숫자를 나란히 놓고 **그 차이를 항목별로 분해**해서
"현장에서는 남았는데 왜 회사에는 안 남았는가"에 답한다.

## 2. 배경 및 문제 정의

수주형 엔지니어링 기업의 원가 회계에는 두 가지 공백이 반복해서 생긴다.

- **일반적인 ERP는 고정비와 변동비를 구분해 주지 않는다.** 계정과목은 있지만
  원가행태(조업도에 비례하는지)가 없어서, 현장 이익과 회사 이익의 간극을
  설명할 수 없다.
- **설계 인력의 맨데이(투입 인건비)가 원가에 안 잡히는 경우가 많다.** 급여는
  판관비로 한 덩어리로 처리되고 현장에 배분되지 않는다. 그 결과 프로젝트
  이익률이 실제보다 과대표시된다.

즉 **간극 = 배부되지 않은 고정비 + 계상되지 않은 맨데이 인건비**이며, 이 값을
계산해 보여주는 것이 이 기능의 존재 이유다.

부수적으로, 분류가 안 된 거래는 변동비도 고정비도 아니어서 **손익에서 통째로
빠진다.** 그러면 원가가 과소계상되어 이익이 부풀려진다 — 이 시스템이 고치려는
문제와 같은 방향의 왜곡이므로, 미분류 금액을 숨기지 않고 노출해야 한다.

## 3. 목표

- 프로젝트별·전사 손익을 2단으로 산출하고, 1단과 2단의 차이를 항목별로 분해
- 고정비와 맨데이 인건비를 프로젝트에 배부해 "진짜 이익률"을 제시
- 원가에서 누락된 금액(미분류·미배부·미귀속)을 **항상 함께 노출**
- 모든 금액 계산을 자동 검증(회귀 테스트)해 숫자를 신뢰할 수 있게 만든다

## 4. 범위

**포함**
- 원가행태(변동/고정/해당없음) 분류 및 계정과목 자동 판정
- 부가세 분리 — 손익은 공급가액 기준으로 계산
- 공헌이익(1단) 계산: 프로젝트 매출 − 변동비
- 고정비 풀 구성 및 프로젝트 배부(배부기준 선택 가능)
- 차입금 이자 계산 및 고정비 풀 포함
- 맨데이 인건비 계산(`인원 × 일수 × 일단가`) 및 프로젝트 원가 반영
- 진짜 영업이익(2단, 세전) 계산 및 1단−2단 차이 분해
- 누락 금액 노출: 미분류 / 원가행태 미등록 계정 / 현장 미귀속 변동비
- 조회 화면(브리핑·프로젝트 상세)과 리포트 생성

**제외**
- 원장 통합·컬럼 매핑·표기 정규화 → P0-1
- 수주 시뮬레이션 → P0-4
- **법인세** → 아래 5.3 참조. 이 구조에 넣지 않는다.
- 세무 신고, 전표 확정, 지급 승인

## 5. 설계 결정

### 5.1 2단 손익 구조

```
[1단] 공헌이익 (현장이익)
      = 프로젝트 매출 − 변동비

[2단] 진짜 영업이익 (세전)
      = 공헌이익 − 배부된 고정비 − 맨데이 인건비
        ※ 배부된 고정비에는 차입금 이자가 포함된다
```

원가행태 판정 기준은 **프로젝트 물량에 비례하면 변동, 수주가 없어도 나가면
고정**이다.

### 5.2 2단은 '세전'이다

회계 기준으로 영업이익은 이자비용을 빼지 않는다(영업외비용). 이 시스템은 이자를
고정비 풀에 넣어 함께 배부하므로 2단은 엄밀히 영업이익이 아니라 **세전이익(경상
이익)에 가깝다.** 이름은 현장에서 굳어진 용어라 유지하되, 화면·리포트에는 반드시
**(세전)** 을 병기한다.

### 5.3 법인세를 넣지 않는 이유

- 이 기능이 푸는 문제(고정비 미배부·맨데이 누락)와 무관하다. 세금은 ERP도
  세무사도 이미 계산하므로 "안 보이던 항목"이 아니다.
- 법인세는 전사 단위로만 산출된다. 현장별로 배부하면 **자의적 배부를 하나 더
  만드는 것**이고, 그건 이 기능이 비판하는 방식이다.
- 누진세율과 세무조정(손금불산입·이월결손금·세액공제)이 얹혀서 `이익 × 세율`
  추정은 확정세액과 어긋난다. 틀린 숫자에 확신을 주면 전체 신뢰가 깎인다.

**타이밍 주의.** 법인세는 발생이 당기, 납부가 이듬해다. 부가세도 분기 납부다.
즉 **2단 이익 ≠ 지금 쓸 수 있는 현금**이다. 자금 관점이 필요해지면 손익을
3단으로 늘리지 말고 별도 화면으로 만들고, 법인세는 추정하지 말고 세무사
산출액을 설정에서 입력받는다.

### 5.4 모르는 것은 모른다고 남긴다

규칙에 안 걸리는 거래는 `미분류` 로 두고 변동비·고정비 어느 쪽에도 넣지 않는다.
억지로 끼워 맞추면 손익이 조용히 틀어진다. 대신 미분류 총액을 **항상** 노출하고,
"미분류를 전부 원가로 인정하면 이익이 얼마가 되는가"를 함께 제시한다.

## 6. 사용자 및 시나리오

**대상 사용자**

| 사용자 | 쓰는 화면 | 관심 |
|---|---|---|
| 대표 | 아침 브리핑, 리포트 | 지금 남는지, 왜 안 남는지 |
| 경영지원·경리 | 데이터, 설정, 프로젝트 상세 | 분류 수정, 고정비·차입금 등록, 맨데이 입력 |

메뉴는 역할로 나눠 표시한다. 다섯 화면이 같은 무게로 나열되면 대표가 열자마자
"내가 이걸 다 조작해야 하나"로 읽는다. 기능을 감추는 게 아니라 누구 화면인지를
드러낸다.

**주요 시나리오**

1. 대표가 아침 브리핑을 열어 전사 공헌이익률과 진짜이익률(세전)을 나란히 본다.
   차이가 큰 이유(고정비 배부액/맨데이/이자)가 항목별로 분해되어 있다.
2. 대표가 저수익·적자 경고에 걸린 현장을 눌러 폭포차트로 어디서 빠졌는지 본다.
3. 경리가 미분류로 남은 거래를 확인해 계정을 지정한다. 지정 결과는 재분류에도
   보존된다.
4. 경리가 차입금을 등록하면 월 이자가 즉시 표시되고 고정비 풀에 반영된다.
5. 실무자가 프로젝트별 맨데이(역할·인원·일수)를 입력하면 그 현장의 진짜이익률이
   갱신된다.

## 8. 데이터 모델

P0-1의 통합 원장을 기반으로 하며, 손익 계산에 필요한 필드를 추가한다.

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `projects` | id, name, client, start_date, end_date, contract_amount | 수주 프로젝트 마스터 |
| `transactions` | id, date, project_id, vendor, description, account, tx_type, amount, amount_incl_vat, cost_behavior, source_file, is_manual_override, is_duplicate_suspect | 거래 원장 |
| `loans` | id, name, principal, annual_rate, start_date, end_date | 차입금 (이자비용) |
| `fixed_costs` | id, name, monthly_amount, category | 월 고정비 |
| `mandays` | id, project_id, role, headcount, days, daily_rate | 설계 인력 투입 |
| `settings` | key, value | 고정비 배부기준, 이자 출처 등 |

**제약**

- `tx_type` ∈ `매입` / `경비` / `매출`
- `cost_behavior` ∈ `변동` / `고정` / `해당없음` (매출 행과 미분류 행은 `해당없음`)
- `amount` = **공급가액**. 손익 계산은 항상 이 값을 쓴다.
- `project_id` NULL 허용 → **공통비**(프로젝트 미귀속). 고정비 배부의 대상.
- `is_manual_override = 1` 인 행은 재분류가 덮어쓰지 않는다.
- `is_duplicate_suspect = 1` 은 표시만. 삭제 판단은 사람이 한다.
- 통화는 원(KRW) **정수** 저장. 비율(이율)만 실수.

## 9. 예외 처리 및 검증 규칙

- 날짜를 못 읽은 행 → 기간 귀속이 불가능하므로 적재에서 제외하고 건수를 알린다
- 계정을 판정할 수 없는 행 → `미분류`. 추측으로 채우지 않는다
- 원가행태 매핑에 없는 계정 → 적재 시점에 경고. 금액이 사라지는 경로다
- 수정세금계산서(음수 금액) → 정상 거래로 취급. 절대값 비교로 검증한다
- 배부 대상이 0개이거나 배부기준 합이 0 → 배부하지 않고 전액을 미배부로 남긴다
- 반올림이 필요한 배부 → 잔차를 특정 대상에 몰아주어 **합계를 보존**한다
- 사람이 입력한 계정·원가행태가 허용 집합을 벗어나면 저장을 거부한다

## 10. 성공 기준

- [x] 프로젝트별·전사 공헌이익(1단)과 진짜 영업이익(2단, 세전)이 산출된다
- [x] 1단과 2단의 차이가 배부고정비·직접고정비·맨데이·이자로 분해된다
- [x] 손익 항등식이 회귀 테스트로 고정된다
      — `공헌이익 − 배부고정비 − 직접고정비 − 맨데이인건비 = 진짜영업이익(세전)`
- [x] 고정비 배부 총액이 원본 총액과 일치한다(반올림 잔차 포함)
- [x] 미분류 총액·비율이 화면에 항상 노출된다
- [x] 원가에서 새는 세 경로(미분류/미등록 계정/현장 미귀속 변동비)가 모두 집계된다
- [ ] **미분류를 원가로 인정한 보정 이익이 화면에 함께 표시된다** (F24 — 적재
      스크립트에만 있다. 이익 과대표시가 이 기능의 핵심 주제인데 정작 화면에서
      두 숫자를 나란히 볼 수 없는 상태다.)
- [ ] 자료 기간이 다른 구간에 화면 경고가 표시된다 (F28 — 미구현)
- [ ] 분석 창 이전 원가가 있는 현장이 표시된다 (F29 — 미구현)
- [ ] 맨데이 인건비가 실제 투입 기준으로 반영된다 (자료 미수령)

## 11. 비기능 요구사항

- **모든 금액 계산은 자동 검증한다.** 금액·비율을 산출하는 함수는 테스트 없이
  병합하지 않는다. 최소한 정상 케이스와 0/빈 데이터 경계 케이스를 포함한다.
- 계산 로직은 UI 레이어에 두지 않는다. UI에 계산식이 들어가면 테스트가 불가능하다.
- **추적성** — 모든 거래 행은 원본 파일명을 보유한다. 숫자를 의심할 때 원본
  엑셀까지 되짚을 수 있어야 한다.
- 실시간 처리는 불필요하다. 업로드 → 분석 → 조회의 배치 방식.
- 실데이터는 저장소에 포함하지 않는다. 경로 제외(`.gitignore`)와 커밋 차단
  훅으로 이중 방어한다.

## 12. 열린 이슈 / 확인 필요 사항

**자료 미수령으로 막힌 것**

- **맨데이(타임시트)** — 급여대장이 월별 집계이고 프로젝트 칸이 비어 있어
  현장별 인건비를 산출할 수 없다. 현재는 급여 전액을 고정비 풀로 배부 중이다.
  이 상태에서는 매출은 있는데 원가가 인건비뿐인 현장이 **이익률 100%로 표시**된다.
  이 기능이 고치려는 문제가 바로 그것이므로, 타임시트 확보가 최우선 과제다.
- **계약금액** — 프로젝트 마스터 미수령. 계약 대비 진행률·초과원가를 볼 수 없다.
- **차입금** — 자료 미수령. 이자 0원으로 계산 중.
- **4대보험 회사부담분** — 분리 불가. 표시 없는 가정값을 원장에 넣지 않는
  원칙에 따라 적재 보류.

**결정이 필요한 것**

- **기간 처리 방침.** 자료 수령 컷오프가 파일마다 달라 이익률이 크게 흔들린다.
  전사 추이는 원가 자료가 완전한 구간으로 자르고, 프로젝트 손익은 자르지 않되
  경고를 붙이는 방향이 타당하다(현장은 여러 달에 걸쳐 진행되므로 자르면
  거꾸로 왜곡된다). **하나의 전역 필터로 두 화면을 덮으면 반드시 한쪽이 틀어진다.**
- **좌측 절단.** 분석 창 시작 이전에 착수된 현장은 과거 원가가 창 밖에 있어
  원가율이 과소 표시된다. 표시 방법을 정해야 한다.
- **애매한 계정의 원가행태.** 사무실용과 현장용이 한 계정에 섞이는 항목
  (전기료·주유비·복리후생비·소모품비·지급수수료 등)은 잠정적으로 고정으로 두고
  "검토 권장"으로 표시하고 있다. 틀려도 금액이 사라지지 않는 쪽을 택한 것이며,
  대표·경리와 합의되면 확정한다.
- **마진 0 통과거래.** 매출과 원가가 동일 금액·동일 일자로 잡히는 거래는
  원가율 100%로 전사 평균을 끌어내린다. 성격(대리 매입/재판매)을 확인해
  손익에 포함할지 정해야 한다.
- **가정값 표시.** 자료가 없어 추정한 값과 실적값을 화면에서 구분해야 한다
  (`실적`/`가정` 태그). 미구현.

## 13. 후속 연계

- 이 기능의 산출물(프로젝트별 공헌이익·진짜이익률, 고정비 배부액, 맨데이 원가)은
  P0-3 대시보드/AI 리포트의 입력이 된다. 리포트 화면은 이미 이 기능에 포함되어
  구현돼 있다.

  수주의 예상 공헌이익에서 배부고정비와 맨데이를 차감해 세전 기준으로 판단한다.
